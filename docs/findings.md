# 실측으로 알아낸 것

측정으로 확정한 것만 적는다. 값의 근거가 필요할 때 여기를 본다.

## 1. 이동이 거친 원인 — 두 성분의 합

팔이 움직일 때 "삐그덕" 거리는 현상을 100 Hz 로 기록해 분해한 결과다.

| 성분 | 정체 | 크기 | 근거 |
|---|---|---|---|
| **J3 토크 리플** | 모터 회전당 약 3.8 사이클의 주기 성분. 4극쌍 모터의 전기각 리플(전류 오프셋) 또는 유성기어 맞물림 | 잔차 12% — **주범** | 출렁임 주파수가 속도에 정비례 (세 조건에서 사이클/회전 = 3.80, 3.75, 3.8) |
| J1·J2 구조 공진 | 6.25 Hz 1차 비틀림 모드 | 잔차 4% | 속도를 3.2배 바꿔도 주파수 고정 + 강성 검산 |

**J1 이 커 보인 이유**: 잔차는 4% 로 작지만 지렛대가 650 mm 라 팔끝에서 크게
보인다.

**J3 만 유독 심한 이유**: 기어비가 50.5 로 절반이라 (1) 같은 관절속도에서 모터가
절반으로 돌아 리플이 잘 보이는 저주파(2~4 Hz)에 떨어지고, (2) 감속비가 낮아
토크 리플이 덜 희석된다.

**위치 정확도에는 영향이 없다.** 속도 리플이지 위치 오차가 아니다. 도달 오차는
0.01 mm 대를 유지한다.

### 결정타가 된 측정 — 구간 x 채널 분해

    정속 구간 잔차 (추세 제거 후 RMS / 최고속도)
                  TCP      J1      J2      J3
    관절 이동    0.082   0.043   0.047   0.120   <- J3 가 3배

    J3 출렁임 주파수:  6.0 deg/s 에서 3.2 Hz / 4.6 에서 2.4 Hz / 6.8 에서 3.5 Hz
    -> 주파수 / 모터회전수 = 3.8 사이클/회전으로 일정 -> 회전에 물린 성분

관절 자체가 출렁였으므로 기하나 추정 문제가 아니라 실제 진동으로 확정했다.

### 측정으로 기각된 가설

| 가설 | 검증 | 결과 |
|---|---|---|
| 브레이크 끌림 | J1 vs J2 주행토크 (같은 감속기) | J1 6.2 < J2 9.5 N·m. 기각 |
| 축별 스틱슬립 | 감속 구간 속도 파형 | 0회. 기각 |
| 서보 게인 / goal tolerance | 헌팅·크리프 카운트 | 0회. 기각 |
| 축 간 종료시각 불일치 | 정지시각 편차 | 0~40 ms. 기각 |
| phi 변화(기하) | 예측 변동 1.03~8.5 vs 실측 | 무상관(+0.23). 기각 |
| 직선모드가 처방 | 관절 vs 직선 비교 | 차이 없음. 기각 |
| 공진이 주범 | acc 4.0(여기율 0.98) vs 6.25(0.00) | 리플 차이 없음. 부수 성분으로 격하 |

### 소프트웨어 밖에 남은 개선 여지

- PANATERM 에서 드라이브 토크리플 보상 / 전류 튜닝 — J3 리플의 근본 대응
- Designer 의 작업공간 속도 한계 상향
- J3 는 빨리 돌수록 리플이 덜 거슬리는 고주파로 올라간다

## 2. 공진 주파수 6.25 Hz

이동 중 TCP 가속도를 100 Hz 로 기록하고, 속도가 다른 26개 구간의 스펙트럼을
봤다. 속도를 3.2배(90 -> 286 mm/s) 바꿔도 봉우리가 6.25 ± 0.90 Hz 로 고정됐다.
**주파수가 속도와 무관하면 궤적 문제가 아니라 구조 공진이다.**

검산: J1 축 둘레 관성 J = 0.756 kg·m² (시험 자세) -> K = J(2πf)² =
1165 N·m/rad = 0.34 N·m/arcmin. PQ003 급 소형 유성감속기의 통상 비틀림 강성
범위(0.2~1)에 들어간다.

**왜 중요한가**: 6 Hz 는 사람이 개별 충격으로 느끼는 대역이다(초당 6번).

사다리꼴 속도 프로파일의 가속 램프가 이 공진을 여기한다. 잔류 진동 크기가
|sin(π·f·T_a)| 에 비례하므로 **가속 시간 T_a 를 공진 주기의 정수배로 잡으면
이론상 0** 이 된다. 램프 시작에서 여기된 진동을 램프 끝에서 상쇄하는 것으로,
input shaping 과 같은 원리다.

여기율이 0 이 되는 가속 배수는 6.25 / 3.125 / 2.083 이고, 기본값으로 3.125 를
쓴다 (`motion.ACC_RATIO_ZERO_VIB`).

## 3. TCP 속도 한계 250 mm/s

컨트롤러의 작업공간 속도 한계다. 넘는 지령을 주면 컨트롤러가 순간마다 속도를
조여서 끊긴다. J1 은 지렛대가 650 mm 로 길어 제일 먼저 걸린다.

`motion.tcp_speed_cap()` 이 이동 반경을 보고 관절속도 상한을 계산해 한계의
85% 안에서 움직이도록 자동으로 잘라 준다.

## 4. 자기충돌 모델과 작업공간

박스 한계 대신 CAD 형상 기반 검사를 쓰면 작업공간이 넓어진다. 자기충돌은
q1 과 무관하고 (q2, q3) 만으로 결정되므로 2차원 문제다 — 지지구조물이 원점
중심 회전대칭이기 때문이다.

**z 간격이 작은 쌍을 "층이 다르다" 고 빼면 안 된다.** 처음에 z 구간이 안 겹치는
쌍을 검사에서 제외했더니, CAD 명목 간격이 2~4 mm 뿐인 쌍까지 빠졌다:

    l2_body    <-> base_pillars   명목 4 mm
    j3_reducer <-> base_pillars   명목 2 mm

실물에는 볼트 머리·와셔·처짐·공차가 있어 2 mm 는 없는 간격이나 같다. 이 여유를
넣기 전에 베이스 근처에서 실제로 충돌이 났다. 지금은 `Z_MARGIN_M = 8 mm` 로
같은 층 취급하며, 검사쌍이 24 -> 28 로 늘었다.

자기충돌이 절대 일어나지 않는 최대 대칭 박스는 **J2 ±110 / J3 ±155** 다.
경계는 실제 경계다 — J3 를 156도로 한 칸만 넓히면 최소 틈새가 10.4 -> 8.0 mm 로
여유 기준 아래로 떨어진다.

이 값을 반영해 소프트웨어 한계를 J2 ±94 -> ±110, J3 ±139 -> ±154 로 넓혔고
(J3 의 154 는 컨트롤러 155 에서 1도 뺀 완충), TCP 도달 격자점이 2959 -> 3107 개로
**5% 늘었다.** 넓힌 뒤에도 한계 안 최소 틈새는 12.8 mm 로 여유 기준 10 mm 를
지킨다.

박스는 계획을 거르는 1차 관문일 뿐이고, 실제 관문은 모든 계획 경로에서 도는
`collision.check_self_collision()` 이다.

## 5. phi 자유도

위치 (x, y) 만 주면 phi 는 자유도로 남는다. 이것을 직전 자세에서 물려받으면
목표점이 관절 한계를 넘는 자세를 요구하는 일이 잦다. 격자점 135개 기준으로
phi 를 고정하면 42개, 자동 선택하면 96개가 도달 가능했다 — **2.3배 차이다.**

`motion.auto_phi()` 가 한계·특이점·충돌을 전부 통과하는 후보 중 관절 여유가
최대인 것을 고른다. 다만 현재 phi 에서 ±60도 창 안을 우선한다. phi 를 크게
바꾸면 이동이 6배 느려지기 때문이다.

## 6. 측정 방법론

- 컨트롤러 상태 갱신은 **정확히 100 Hz**. `get_status()` 한 번에 관절각·속도·
  토크·포즈·twist 가 다 온다.
- 더 빨리 폴링하면 **중복 표본**이 섞인다. `time_stamp` 로 거를 것.
- TCP 속도는 차분하지 말고 **`actual_twist`** 를 쓸 것.
- **채널(관절/TCP)과 구간(가속/정속/감속)을 분해**하면 원인이 드러난다.
  합쳐 놓으면 모든 가설이 그럴듯해 보인다.
- **부정 결과도 결과다.** 가설 셋을 한꺼번에 기각하는 실험이 진짜 원인으로 가는
  길을 열었다.
- **원인 확정은 독립적인 두 측정이 같은 방향을 가리킬 때만.**
- 요약 통계보다 **원시 파형**을 볼 것.
