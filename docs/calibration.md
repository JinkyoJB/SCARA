# 정합 — 실물과 가상을 같은 좌표로

목표는 하나의 코드로 실물과 Isaac Sim 을 똑같이 제어하는 것이다. 그러려면
같은 명령이 같은 자세를 만들어야 한다.

**컨트롤러가 읽는 관절각은 그 자체로는 아무 물리적 의미가 없다.** 모터가 어디에
놓여 있느냐에 따라 임의로 정해진 값이다. 이 문서는 그것을 모델이 정의한 자세에
묶는 절차다.

맞춰야 할 것은 세 가지뿐이다: **원점, 회전 방향, 링크 길이.**

## 1. 좌표·부호 약속

**모든 각도와 좌표는 위에서 내려다본 기준이다.** 이 약속이 흔들리면 아무것도
못 맞춘다.

| | 정의 |
|---|---|
| +z | 위 (천장 방향) |
| +x | 영점 자세 q=[0,0,0] 에서 팔이 뻗는 방향 |
| +y | +x 에서 반시계 90도 = 왼쪽 |
| + 각도 | **위에서 내려다볼 때 반시계(CCW)** |

```
        +y (왼쪽)
         ^
         |      (반시계) = +
         |
         +-----------> +x  (영점에서 팔이 뻗는 방향)
       원점
    (J1 회전축)            +z = 위
```

수학적으로는 +z 축 둘레 오른손 법칙이다.

| 각 | 무엇으로부터 재는가 |
|---|---|
| q1 | +x 축으로부터 링크1 까지 (절대각) |
| q2 | 링크1 의 연장선으로부터 링크2 까지 (상대각) |
| q3 | 링크2 의 연장선으로부터 링크3 까지 (상대각) |
| phi | q1 + q2 + q3 — TCP 가 향하는 절대 방향 |

**말이 헷갈릴 때 쓰는 물리 시험** — "반시계" 라는 단어를 안 쓰고 확인하는 방법:

> 베이스 뒤에 서서 팔이 뻗는 쪽(+x)을 바라본다.
> +q1 을 주면 팔끝이 **내 왼쪽**으로 간다. 그러면 부호가 맞다.

q2, q3 도 같다. + 는 앞 링크 기준으로 왼쪽으로 꺾이는 방향이다.

주의:

- **"위에서" 가 핵심이다.** 아래나 옆에서 보면 반시계/시계가 뒤집힌다.
- z 는 −44 mm 로 고정이며 제어할 수 없다. 세 관절축이 모두 연직이기 때문이다.
- 원점은 J1 회전축이다. 팔 자세와 무관하게 고정된 유일한 점이다.

## 2. 원점 — q=[0,0,0] 의 정의

    q=[0,0,0] 은 세 링크가 완전히 펴진 일직선 자세이며,
    그 일직선(= 베이스 +x 축)이 베이스 판 앞모서리에 수직.

이 문장이 `config.ZERO_POSE_DEFINITION` 에 그대로 들어 있다. 엔코더가
초기화되거나 기구를 분해했다 재조립하면 이 문장이 영점을 되살릴 유일한 근거다.

J2·J3 는 "팔이 일직선" 이라는 물리 조건이 자세를 결정하므로 선택의 여지가 없다.
J1 은 그 일직선이 공간에서 어디를 향하느냐라서 사람이 정한다.

확인: 영점에서 TCP 가 (650.00, 0.00, −44.00) mm 여야 한다.

### 설정 절차

`python sw/main.py` 의 1단계가 이 절차다.

1. 팔이 이미 일직선이고 q 도 0 이면 그대로 통과
2. 팔은 일직선인데 q 가 0 이 아니면 -> 지금 자세를 0 으로 선언
3. 일직선이 아니면 -> 손과 조그로 편 뒤 선언

**역구동성이 축마다 다르다.** J3(50.5:1)만 손으로 돌아가고, J1·J2(100:1)는
조그를 써야 한다. 조그를 쓰면 서보가 켜지므로 그 뒤에 손으로 밀면 모터와
힘겨루기가 되어 과부하(Err16.0)가 난다.

`SCARA.declare_zero()` 는 서보 OFF 전후 각도를 둘 다 읽어 흘러내린 양(drift)을
보정해서 박는다. 이 보정을 안 하면 흘러내린 자세가 0 으로 박히는데, 검사는
**항상 통과한다** — 같은 좌표계 안에서 스스로를 검사하기 때문이다.

### 영점은 런타임 값이다

`calibrate_joint_angle` 이 설정하는 오프셋은 **Designer 에서 설정을 바꿔
적용하면 프로젝트의 옛 값으로 되돌아간다.** 영구 저장은 Motion Studio 의
origin calibration (Encoder Offset, 펄스 단위) 뿐이다.

또 이 명령은 적용 직후 **드라이버를 EtherCAT OP 밖으로 내보낸다.** 세 축이
Err80.x 로 폴트에 빠지고 제어 루프가 멈추며, `reset_trigger()` 로는 안 풀린다.
Designer 를 다시 연결해 Step 4 를 밟아야 한다. `main.py` 가 이것을 감지해서
안내하고 기다린다.

### 영점이 맞는지는 사람만 확인할 수 있다

컨트롤러는 위치 폐루프라 **언제나** q=[0,0,0] 을 보고한다. 그건 "지령대로 갔다"
는 뜻이지 "물리적으로 그 자세다" 는 뜻이 아니다. 순환논리를 깨는 유일한 방법은
일직선 자세로 보낸 뒤 사람이 눈으로 보는 것이다 (`SCARA.verify_zero()`).

`tools/check_zero.py` 는 여기에 정량 확인을 더한다. 왕복 후 J1 축~TCP 직선거리를
자로 재면 일직선일 때 650.0 mm 이고, J2 가 굽은 만큼 짧아진다:

    10도 -> 647.7    20도 -> 640.7    30도 -> 629.1    45도 -> 603.3

## 3. 회전 방향

세 축이 전부 규약대로(+q = 위에서 볼 때 반시계) 돌아야 한다.
`config.DIRECTION_SIGN` 이 (1,1,1) 이 아니면 `safety.check_direction_sign()` 이
모든 이동을 막는다.

**반전은 컨트롤러 한 곳에서만 한다**: Designer -> Step 3 -> Joint Mapping ->
Transmission Parameters -> Reduction ratio 의 부호.

파이썬에서만 뒤집으면 안 되는 이유는 `kinematics.py` 와 StellaX 내장 FK/IK 가
같은 규약을 공유하기 때문이다(소수점 6자리 일치 확인). 파이썬만 고치면 컨트롤러
내장 IK, Designer 조그 버튼, 티치펜던트가 전부 반대로 남는다. 드라이버
607Eh Polarity 로 뒤집는 것도 피한다 — Isaac Sim USD 에 반영할 근거가 코드에
남지 않는다.

이 부호가 틀리면 TCP 가 수백 mm 어긋난다. 실제로 J2·J3 가 반대인 채로 (500, 0)
을 지령했더니 팔이 (96.6, 490.6) = +x 로부터 +78.9도 로 갔다. **오차 635 mm.**
그런데 모델도 컨트롤러도 도착했다고 보고했다 — 둘이 같은 잘못된 규약을 쓰기
때문이다.

확인은 `tools/verify_model.py` 로 한다. 한 번에 한 축만 +60도 움직여서 방향·크기·
영점을 한꺼번에 드러낸다. 세 축이 섞인 IK 결과만 보면 어느 축이 어긋났는지 알 수
없다.

## 4. 다회전 데이터

23bit 앱솔루트 엔코더에 배터리 백업이 붙어 있어 전원을 꺼도 위치를 기억한다.
드라이버 전원 재투입 후에도 영점이 유지되는 것을 확인했다.

잃어버리는 것은 엔코더 값이 아니라 **오프셋 설정**이다. 위 2절 참조.

## 5. Isaac Sim 쪽 정합

USD 를 만들 때 맞춰야 할 것:

| 항목 | 근거 |
|---|---|
| 베이스 +x 축 방향 | `config.ZERO_POSE_DEFINITION` — 베이스 판 앞모서리에 수직 |
| 관절 회전 방향 | +q = 위에서 볼 때 반시계 (세 축 모두) |
| 링크 길이 a | 250 / 250 / 150 mm |
| 링크 높이 d | −23.5 / −20.5 / (툴) mm |
| 질량·COM·관성 | `config` 의 DH 좌표계 값. yaml 원본이 아니다 |
| 관절 한계 | `config.CONTROLLER_JOINT_LIMITS_RAD` |

정합 확인은 같은 관절각을 실물과 USD 에 넣고 TCP 좌표를 비교하는 것으로 한다.
영점 자세에서 (650, 0, −44) mm 가 나오는지가 첫 관문이다.

## 6. 증상별 원인

| 증상 | 원인 |
|---|---|
| 영점에서 팔이 일직선이 아니다 | 오프셋이 되돌아갔다. 다시 선언 |
| 팔은 일직선인데 q 가 0 이 아니다 | 〃 |
| 지령 방향과 반대로 돈다 | 회전 방향 부호 |
| TCP 가 수백 mm 어긋난다 | 회전 방향 부호 (한 축만 반대여도 이렇게 된다) |
| TCP 가 수 mm 어긋난다 | 링크 길이 / 기구학 캘리브레이션 |
| 지령은 받는데 안 움직인다 | 주회로 전원 또는 EtherCAT OP — controller.md |
