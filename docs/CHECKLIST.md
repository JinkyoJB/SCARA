# 코드 쓰기 전 체크리스트

새 스크립트나 기능을 만들기 전에 훑는다. 아래는 전부 실제로 당한 것들이다.

## 하드웨어가 소프트웨어를 배신하는 지점

| 함정 | 증상 | 상세 |
|---|---|---|
| **`calibrate_joint_angle` 은 드라이버를 EtherCAT OP 밖으로 낸다** | 직후 3축 `Err80.x (0xFF50)`, 제어루프 정지. `reset_trigger()` 로 **안 풀림** | [calibration.md](calibration.md) |
| **영점은 런타임 값** — Designer 설정 변경·적용 시 옛 값으로 되돌아감 | 팔은 그대로인데 q 가 딴 값 | 〃 |
| **영구 저장은 Motion Studio origin calibration (Encoder Offset) 뿐** | `front_save_configuration` / `front_save_default` 는 UI·기본선택 저장이라 무관 | 〃 |
| **주회로 전원(L1/L3)을 빠뜨려도 통신·엔코더·FK/IK 는 정상으로 보인다** | `servo(True)` 순간 `Err88.0`. 토크가 정확히 0.0 | [controller.md](controller.md) |
| **Designer Step 4 Verification 을 해야 EtherCAT 이 OP 로 올라온다** | 지령은 받는데 안 움직임 | 〃 |
| **제어루프가 멈추면 status 는 죽기 직전 스냅샷** | `pds`/`ready`/`servo_on` 을 믿으면 안 됨. `time_stamp` 로 판별 | 〃 |
| **J1·J2 는 100:1 이라 손으로 역구동 불가** (J3 만 50.5:1 로 가능) | "손으로 펴세요" 안내가 막힌다 | [hardware.md](hardware.md) |
| **TCP 속도 한계 250 mm/s** — 넘기면 컨트롤러가 순간마다 조여서 끊긴다 | J1 이 지렛대가 길어 제일 먼저 걸린다 | [findings.md](findings.md) |
| **종료할 때 `stop()` 만으로는 부족** — 정지 확인 후에 서보를 꺼야 한다 | 궤적이 살아있는 채 서보를 떨구면 `Err16.0` | [software.md](software.md) |
| **서보 ON 상태에서 손으로 밀면 과부하** | 조그는 서보를 켠다. 그 뒤 손으로 밀면 모터와 힘겨루기 -> `Err16.0` | |
| **토크 가드 문턱은 감속기 한계가 아니라 실측 주행토크 기준** | 연속한계 29 N·m 의 80%(=23.2)는 영영 안 걸린다. 실측은 J1 6.2 / J2 9.5 / J3 4.3 | |
| **막힌 축을 계속 밀면 `Err16.0`** | 지령 후 위치가 안 변하면 즉시 정지시킬 것 (`JOG_STALL_SEC`) | |

## 종료·중단 절차 (고정)

    stop()  ->  check_finish() 로 정지 확인 (최대 2초)  ->  servo(False)  ->  close()

`stop()` 은 감속을 시작만 한다. `SCARA.close()` 가 이 순서를 지킨다. 새 코드에서
직접 서보를 끌 일이 있으면 같은 순서로.

## 안전 원칙

1. **영점이 불명확하면 자동으로 큰 이동을 하지 않는다.** 컨트롤러가 믿는 각도와
   실제 팔이 어긋나 있어서 충돌 검사의 입력부터 틀리다. 손 정렬 + 10도 이하 조그만.
2. **모든 계획 이동은 충돌 검사를 지난다** (목표 + 경로 중간 샘플링).
   단, 영점 불명 시엔 검사를 믿지 말 것 (1번과 같은 이유).
3. **z 간격이 작은 쌍을 "층이 다르다" 고 빼지 않는다.** 명목 2~4 mm 는 볼트머리·
   공차 앞에서 없는 간격이다 (`Z_MARGIN_M = 8 mm`).
4. **영점 검증은 사람 눈으로만 가능하다.** 컨트롤러는 언제나 "지령대로 갔다" 고
   보고한다.
5. **절대 실패하지 않는 검사는 검사가 아니다.** 가드를 짤 때 "이게 실패할 수
   있나" 를 먼저 자문할 것.

## 진단할 때

- **원인 확정은 독립적인 두 측정이 같은 방향을 가리킬 때만.**
- **부정 결과도 결과다.** 가설을 한꺼번에 기각하는 실험을 아까워하지 말 것.
- **채널(관절/TCP)과 구간(가속/정속/감속)을 분해**하면 원인이 드러난다.

## 측정할 때

- 컨트롤러 상태 갱신은 정확히 100 Hz. `get_status()` 한 번에 다 온다.
- 더 빨리 폴링하면 중복 표본이 섞인다. `time_stamp` 로 거를 것.
- TCP 속도는 차분하지 말고 `actual_twist` 를 쓸 것.
- 요약 통계보다 원시 파형.
